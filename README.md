# 과학기술정책 국무회의 아카이브

국무회의의 **의결(무엇이 제도화됐나)** 과 **담론(어떤 논리로)** 을 회차 키로 이어
붙인 뒤, 과기정통부·산업부 축으로 재단한 연구용 데이터셋과 공개 대시보드.

기획안: `~/.claude/plans/https-opencabinet-pages-dev-snappy-pretzel.md`

## Phase 0 실측 결과 — 계획을 바꾼 사실들

착수 전 세운 가정 중 다섯 가지가 실측에서 뒤집혔다. 모두 데이터 정확도에
직결되므로 여기 남긴다.

### ① 아카이브는 69건이 아니지만, 쓸 수 있는 구간은 2018-09부터다

[국무회의 브리핑 목록](https://www.korea.kr/briefing/stateCouncilList.do)은
`startDate`/`endDate`를 안 주면 **최근 1년만** 보여준다. 기본 호출로는 69건이지만
범위를 넓히면 1,498건이다.

다만 **"1998년까지 1,498건"은 부정확했다.** 실측으로 정정한다.

| 사실 | 확인 결과 |
|---|---|
| 목록 자체의 시작 | **2004년** (1998~2003 조회 시 0건) |
| 안건 전수(「의사일정」 첨부) 시작 | **2018-09-04 제38회** |
| 2018-08 이전 | 「결과보도자료」만 — 안건 전수 문서 없음 |

의사일정 첨부가 없으면 안건을 전수로 못 뽑으므로 같은 파이프라인으로 다룰 수
없다. 그래서 수집 범위를 **2018-09 ~ 2026-07**로 잡았다. 447개 회의 중
444개(99.3%)에서 의사일정을 확보했다(결측 3: 첨부 부재 2 + 서버 오류 1).

### ② 회차는 정규·임시가 연번을 공유한다 — 종류는 키가 아니다

회의키를 `(연도, 종류, 회차)`로 잡으면 **한 회의가 둘로 갈라진다.**

```
2025년: 정규 ∪ 임시 = 제25~57회  (임시 29·39회, 제35회만 결번)
2026년: 정규 ∪ 임시 = 제1~32회   (임시 8·12·15·32회, 결번 없음)
```

게다가 같은 회의의 문서끼리도 '임시' 표기가 흔들린다. 2026-04-11에
`제15회 임시 국무회의 브리핑`과 `제15회 국무회의 결과 브리핑`이 나란히 있다.

→ **회의키 = `(연도, 회차)`**. 종류는 속성이며, 문서 제목들을 모아
`merge_kind()`로 판정한다. `tests/test_meeting_key.py`에 고정.

### ③ 안건 전수는 '의사일정' 첨부에만 있다

브리핑 본문도 결과 보도자료도 `심의·의결된 안건 중 **일부 내용**은 다음과
같습니다`라며 주요 안건만 싣는다. 제30회는 **27건 의결 중 6건**만 상세.

| 출처 | 제30회 안건 노출 |
|---|---|
| 브리핑 본문 | 6건 (소관 태그 기준) |
| 결과 보도자료 hwpx | 6건 |
| **의사일정 hwp** | **27건 전수** |

의사일정에는 의안번호·제출월일·제출기관·의안명·차관회의/국무회의 의결결과가
표로 들어 있고, 부처보고·집중토의 안건도 소관과 함께 나온다.

### ④ '모두말씀'은 화자가 구분된 공식 속기록이다

KTV 자막은 `ko/asr(자동생성)`뿐이라 화자 분리가 없다. 그런데 모두말씀 첨부는
화자를 명시한다.

```
▲ 이 대통령 : 그러니까 그런 한계가 있는 것 저도 알죠…
- 윤호중 행안부 장관 : 대통령님, 지방정부는 자치권이 있어 가지고…
```

→ 최소한 모두발언 구간에서는 **ASR 화자 추정이 불필요**하다. Phase 3의 가장 큰
품질 위험과 비용이 함께 줄어든다. 부처보고·토론 구간은 여전히 자막이 필요하다.

### ⑤ kordoc은 CLI가 있어 자동화된다

`.hwp`는 파이썬에서 다루기 까다로운데, kordoc이 MCP 서버이자 CLI다.

```bash
npx kordoc <file> --format json --silent -o -
```

`blocks[].table.cells[][]` 구조를 주므로 주간 자동화가 스크립트로 돌아간다.
(MCP 도구는 스크립트에서 못 부른다.)

## Phase 1 결과 — 안건 데이터셋 확보

먼저 현 정부 64개 회의(2025-06-10 ~ 2026-07-21)에서 **안건 2,190건**을 추출했다.
파싱 실패 0건, 미등록 기관명 0건. 검증 기준값(제30회 법률안 3·대통령령안 18·
일반안건 6)과 일치. 이후 Phase 2에서 2018-09까지 넓혀 **16,742건**이 됐다.

### 실측이 또 바꾼 것 셋

**① 의안 표는 하나가 아니다.** 회차에 따라 절차별로 표가 쪼개진다. 가장 큰 표
하나만 읽으면 나머지가 조용히 사라진다 — 제31회는 29건 중 16건만, 제26회는
39건 중 23건만 잡혔다. 문서가 스스로 밝힌 건수와 대조하는 검사를 넣어 잡았다.

**② `보고안건`은 의결 안건이 아니다.** 차관회의 결과가 `원안접수`로 찍히고
국무회의에 보고만 된다. 일반안건으로 묶으면 의결 건수가 부풀려진다.

**③ 점유율의 분모를 형식 안건이 잠식한다.** 제출기관을 그대로 세면 이렇게 된다.

전 기간(16,742건) 기준:

| 역할 | 건수 | 비중 |
|---|---:|---:|
| 정책안건 | 9,417 | 56.2% |
| 법률공포 | 6,013 | 35.9% |
| 조직직제 | 993 | 5.9% |
| 인사 | 319 | 1.9% |

법제처가 6,110건으로 1위였는데 대부분이 **법률공포안**이다. 국회를 통과한
법률을 공포하는 절차이지 법제처의 정책 발의가 아니다. 행정안전부의 상당수도
타 부처 직제 개정령이다.

→ 의제 점유는 **정책안건 9,417건**을 분모로 낸다.

### 데이터 품질 메모

일부 의사일정은 **머리표 건수와 실제 실린 의안 수가 다르다**(444회 중 39회,
전부 ±2 이내). 안건이 철회됐는데 머리표를 안 고친 경우로, 제53회는 의안번호가
1636→1638로 건너뛴다. 독립 파서(`hwp5html`)로 교차 확인해 문서 자체의
불일치임을 확정했다. **표에 실제 의안번호가 붙은 쪽을 사실로 삼고** 불일치는
`data/export/agenda_parse_report.json`에 남긴다.

## Phase 2 결과 — 과거 회차 확장(2018-09 ~ 2026-07)

수집 범위를 64회 → **447회**로 넓혔다(7배). 안건 **16,742건**, 발언 **4,603건**,
보고·토의 **151건**. 파싱 실패 0 · 부처 시점 문제 0 · 미등록 기관 0.

### 과거 데이터가 드러낸 버그 4건

전부 **터지지 않고 그럴듯하게 틀린 값을 만드는** 종류였다. 최근 데이터만으로는
드러나지 않았고, 검증 리포트(선언 건수 대조·미등록 기관 점검)가 잡아냈다.

**① colSpan 무시 (가장 심각).** kordoc은 병합 셀을 하나로 합치지 않고 첫 칸에
값을 넣은 뒤 나머지를 빈 문자열로 채운다. 6칸짜리 표가 물리적으로 11칸으로
나오는 문서(2023-037, `colSpans=[2,1,2,1,2,1,1,3,1,1,1]`)에서 고정 인덱스로
읽는 바람에 제출월일이 제출기관 칸으로 밀렸다 — `2023.08.29.`가 소관부처로
**42건** 기록됐다. 2025~2026 문서는 colSpan이 대부분 1이라 우연히 안 걸렸을 뿐이다.

**② 선언 건수를 `setdefault`로 셌다.** 같은 유형이 두 표에 쪼개져 나오면
뒤 표를 놓쳤다(2024-042: 일반안건 3건+10건 → 3건만).

**③ ②를 고치다 만든 회귀.** 합산으로 바꿨더니 표 앞 문단 라벨과 표 안 구분행이
**같은 선언을 중복**해 정확히 2배가 됐고, **444회 전부가 불일치로 뒤집혔다.**
`declared_counts`를 `agenda_doc`으로 옮기고 `parse_agenda_items`와 동일한
우선순위(구분행이 있으면 그것만)를 따르도록 재작성했다. 이 로직만 별도 테스트
7건으로 고정(`tests/test_declared_counts.py`).

**④ 일시·장소 줄이 화자로 오인.** `- 2023. 11. 22(수) 08:00, 정부서울청사 -`가
화자 표기와 모양이 같아, 시각의 콜론을 화자 구분자로 읽었다. 단순 오탐이 아니라
**화자 상태를 오염시켜 뒤 문단 전체가 가짜 화자에게 `explicit`으로 귀속**됐다.
화자명이 한글로 시작하도록 제약해 고쳤다 — 화자 81명 → 24명, 가짜 `explicit`
759건 제거(1,228 → 469).

### 8년치가 열어준 분석 — 정권별 비교

단일 시점으로는 안 보이던 것이 드러났다. 최근 1년만 보면 AI가 과기 의제 1위지만
전 기간으로는 에너지가 앞선다. `era_trend.md` 참고.

| 정권 | 정책안건 | 과기정책 관련 | 비중 |
|---|---:|---:|---:|
| 문재인(2018-09~2022-05) | 4,521 | 254 | 5.6% |
| 윤석열(2022-05~2025-05) | 3,765 | 276 | 7.3% |
| 이재명(2025-06~2026-07) | 1,131 | 103 | **9.1%** |

과기정책 비중이 단조 증가한다. AI 안건도 4 → 5 → 12건으로 늘었는데, **태그
사전이 최근 어휘라 과거를 과소 계상한 것 아닌가**를 의심해 제목 원문을 직접
검색해 교차 확인했다(2 → 4 → 11건). 추세는 사전 편향이 아니라 실제 변화다.

## Phase 3-A 결과 — 발언 레이어(모두말씀)

238개 회차에서 **발언 4,603건**을 화자별로 추출했다. 파싱 실패 0건, 화자 24명.

| 근거 등급 | 건수 | 뜻 |
|---|---:|---|
| `explicit` | 469 | 문서에 화자가 표기됨(`▲ 이 대통령 :`) |
| `document_default` | 4,134 | 표기 없는 문단 — 「모두말씀」이므로 대통령 |

**추정은 하지 않았다.** 표기 없는 문단을 대통령으로 보는 것은 문서 정의이지
추론이 아니며, 등급을 나눠 저장했으므로 집계할 때 섞이지 않는다.

### 한계 — 부처별 발언 점유는 이것만으로 못 잰다

발언 4,603건 중 **대통령 발언이 압도적**이고 장관 발언은 수십 건 수준이다.
모두말씀은 대통령 모두발언 위주 문서라, 부처 보고·토론 구간은 거의 담기지 않는다.

→ 이 레이어의 값어치는 **대통령 정책 발언·지시 코퍼스**에 있다. 정책 계보
(발언 → 지시 → 의결)의 앞단이 여기서 나온다. 부처별 발언 점유는 KTV 자막을
붙이는 Phase 3-B의 몫이다.

과기정책 관련 발언은 **151건**(지시성 41건)이며 주제는 에너지 58 · 반도체 38 ·
AI 29 순이다. `president_stc_remarks.md`는 회차별로 **그날의 발언과 그날 의결된
과기 안건을 나란히** 보여준다.

또한 모두말씀 첨부는 **2020-02-25부터** 실린다(의사일정은 2018-09부터). 238개
회차에만 있어 의사일정 444회보다 적다 — 발언 레이어의 커버리지가 의결 레이어보다
좁다는 뜻이며, 두 레이어를 함께 집계할 때 분모를 섞으면 안 된다.

### 분류 정밀도 — `전력` 동음이의어

`전력`을 에너지 키워드로 쓰면 안 된다. 全力(`전력투구`, `전력해 주시기 바랍니다`)과
표기가 같아 실측 11회 중 5회가 오탐이었다. 電力 의미가 확정되는 복합어
(`전력수급`·`전력망`·`전력계통`)만 쓴다. `tests/test_relevance.py`에 고정.

## 데이터 출처와 역할

| 출처 | 얻는 것 | 라이선스 |
|---|---|---|
| korea.kr 브리핑 본문 | 회차·날짜·주요 안건 설명·과(課) 단위 소관·국정과제 연계 | 공공누리 1유형 (출처표시) |
| ├ 첨부 `의사일정.hwp` | **안건 전수** — 의안번호·제출기관·의결결과 | 〃 |
| ├ 첨부 `모두말씀.hwp` | 대통령·국무위원 발언 공식 원문(화자 구분) | 〃 |
| └ 첨부 `결과보도자료.hwpx` | 주요 안건 상세 설명 | 〃 |
| 행안부 국무회의록 | 심의 과정 보강 (게시 약 6주 지연) | 공공누리 |
| KTV 유튜브 자막 | 부처보고·토론 구간 발언 | 링크만, 영상 재배포 안 함 |

**사진·이미지·동영상은 쓰지 않는다** — 연합뉴스·통로이미지 등 제3자 저작권.

### 구조적 한계

**의안 심의는 비공개다.** 안건별 찬반·심의 발언은 어떤 출처에도 없다. 이 데이터로
얻는 것은 *공개 토론의 담론* + *의결의 결과*이며 **그 사이는 빈칸**이다.
연구에서 "국무회의에서 논의되었다"를 주장할 때 반드시 구분해야 한다.

src/

  raw/        원본 스냅샷 — 파서가 틀려도 서버를 다시 안 때리고 재파싱

## 실행

```bash
# 수집 (2018-09~2026-12, 재실행 시 이미 받은 것은 건너뜀)
python3 run_collect_list.py
python3 run_collect_attachments.py

# 파싱
uv run --with pyyaml python run_parse_agendas.py    # 안건 → agenda_items.jsonl
uv run --with pyyaml python run_parse_remarks.py    # 발언 → utterances.jsonl
uv run --with pyyaml python run_parse_reports.py    # 보고·토의 → report_items.jsonl

# 보고서
uv run --with pyyaml python run_report_stc.py                 # 과기 안건 목록(각주 문안 포함)
uv run --with pyyaml python run_report_remarks.py             # 대통령 과기 발언록

## Phase 4 — 공개 대시보드

`site/`에 자기완결 정적 사이트. 빌드 도구 없이 HTML·CSS·JS 3개 파일 + 데이터 번들.

uv run --with pyyaml python run_build_site_data.py   # site/data/bundle.json 생성
python3 -m http.server 4610 --directory site         # 로컬 확인
```

**전체 16,742건을 담되 과기정책 필터를 기본 ON**(1,008건)으로 둔다. 1,008건만
담지 않은 이유는 분류기를 검증할 수 없게 되기 때문이다 — 이 작업에서만 분류
오류를 두 번 잡았고(부처 티어 오탐 103건, `전력` 동음이의어), 걸러진 15,734건이
없으면 "왜 이게 빠졌나"를 확인할 방법이 사라진다. 번들은 gzip 0.42MB라 전량
로드해도 부담이 없다.

**분류는 빌드 때 파이썬이 미리 계산해 굽는다.** 브라우저에서 다시 판정하지
않는다 — 태그 사전과 부처 계보가 파이썬에 있고, 기준이 두 곳에 흩어지면 조용히
어긋난다. `app.js`는 필터·검색·렌더링만 한다.

각 행에 **판정 근거**(`소관 과학기술정보통신부 · 주제어 '인공지능'`)와 **원문
링크**를 붙였다. 근거를 확인할 수 없는 라벨은 연구에 쓸 수 없고, 공공누리
제1유형은 출처 표시가 의무다.

### 배포 (Cloudflare Pages)

`site/`를 출력 디렉터리로 지정하면 된다. 빌드 명령 없음(정적). `_headers`에
캐시·보안 헤더가 들어 있다.

## Phase 5 — Supabase 적재 (계량분석 백엔드)

파싱·분류 결과를 Supabase Postgres(`sci-cabinet`, 서울 리전)에 정규화 테이블로
적재했다. JSON 파일보다 SQL이 계량분석에 낫다 — GROUP BY·윈도우 함수·레이어
조인·시계열 집계를 한 줄로, R(`RPostgres`)·Python(`psycopg2`)·브라우저 SQL 편집기
어디서든.

**테이블** (분류는 파이썬 계산값 그대로 — DB에서 재판정 안 함)

| 테이블 | 행 | 내용 |
|---|---:|---|
| `ministry` | 54 | 부처 안정 ID·현재명·과기 티어 |
| `meeting` | 447 | 회차·개최일·원문 링크 |
| `agenda_item` | 16,742 | 의결 안건 (role·is_stc·tags·소관 정규화) |
| `utterance` | 4,603 | 발언 (화자·근거등급·전문, trigram 검색 인덱스) |
| `report_item` | 151 | 보고·토의 |

**분석용 뷰** — `v_agenda`(부처명·티어·회차·정권 파생), `v_policy_agenda`
(정책안건만 = 점유율 표준 분모), `v_meeting_summary`(회의별 요약).

**보안** — 전 테이블 RLS 켜짐, anon은 **SELECT만**(쓰기 401). 어드바이저 경고 0.
적재는 초기 1회 anon 쓰기로 했고 직후 잠갔다. 재적재 절차는 `load_supabase.sh`
주석 참고.

**의미 검색은 각자 자기 Claude Code로.** 공개 사이트에 API 키를 심지 않는
대신, 연구자가 자기 Claude Code를 이 Supabase에 붙여 자연어로 질의한다
(`body` 컬럼에 한국어 trigram 인덱스가 있어 유사도 검색도 됨).

```bash
uv run --with pyyaml python run_emit_rest_json.py   # REST JSON 생성
./load_supabase.sh <ANON_KEY>                       # 갱신 절차는 스크립트 주석 참고
```
